# ops-automation-portfolio

A workflow automation portfolio built around **Bluefield Supply Co., a fictional wholesale distributor**.
It connects an ERP (ERPNext), a reporting database (Postgres), BI dashboards (Metabase), workflow
automation (n8n), and AI tools, and controls what the AI is allowed to do.

> **Demo data only.** Every company, customer, and number in this repository is fictional.

## Setup

Requirements: [uv](https://docs.astral.sh/uv/) and Git. uv installs Python 3.12 itself.
Docker is needed only from Foundation Step 5 onward.

### GitHub Codespaces (recommended), Linux, or macOS

In a Codespace, the [dev container](.devcontainer/devcontainer.json) installs uv and Docker and runs
`make setup` for you. Use the 2-core machine.

```bash
make setup   # installs Python 3.12 and dependencies, creates .env from .env.example
make lint
make test
```

Run `make help` to see every target.

### Start the Docker services

Services are split into Compose profiles, so you run only what the current task needs:

```bash
make env-secrets      # fill blank passwords and keys in .env with random values
make up               # core: Postgres + Mailpit
make up-reporting     # + Metabase      (make stop-reporting to stop it)
make up-automation    # + n8n           (make stop-automation to stop it)
make up-all           # all four stack services
make erp-up           # ERPNext, from the official frappe_docker pwd.yml (make erp-down to stop it)
make check-stack      # live stack checks; skips profiles that aren't running
make down             # stop every stack service (data is kept)
```

See [infra/README.md](infra/README.md) for URLs, the database layout, browser setup, and troubleshooting,
and [docs/free-tier-limits.md](docs/free-tier-limits.md) for how each command affects the free monthly allowances.

### Windows without make

```powershell
uv python install 3.12
uv sync --locked
uv run ruff check .
uv run ruff format --check .
uv run pytest -m "not integration"
```

## Configuration and secrets

All settings come from environment variables, loaded by `shared/config.py`. Copy `.env.example` to
`.env` and fill in your own values. `.env` is gitignored and must never be committed.

| Variable | Needed from | Purpose |
| --- | --- | --- |
| `APP_ENV` | Now | `dev`, `test`, or `demo` |
| `LOG_LEVEL` | Now | `DEBUG`, `INFO`, `WARNING`, `ERROR`, `CRITICAL` |
| `AI_PROVIDER` | Project 2 | AI provider name |
| `AI_MODEL` | Project 2 | Exact model name. Never hardcoded |
| `AI_API_KEY` | Project 2 | API key. Stored as a secret and masked in logs |
| `POSTGRES_PASSWORD`, `METABASE_DB_PASSWORD`, `N8N_DB_PASSWORD` | Docker stack | Database logins. Generated by `make env-secrets` |
| `MB_ENCRYPTION_SECRET_KEY`, `N8N_ENCRYPTION_KEY` | Docker stack | Encrypt saved credentials in Metabase and n8n. Keep them stable |
| `POSTGRES_USER`, `POSTGRES_DB`, `POSTGRES_HOST`, `*_PORT`, `STACK_TIMEZONE`, `N8N_WEBHOOK_URL` | Docker stack | Optional. Defaults are in `.env.example` |

## Tests

- `make test`: unit tests, which need no running services. CI runs these on every push.
- `make test-all`: also runs tests marked `@pytest.mark.integration`, which need live services.

## Engineering conventions

- Structured JSON logs with a `run_id` (`shared/logging.py`).
- No secrets or AI model names in code.
- Lint (ruff) and unit tests run in GitHub Actions on every push and pull request.
