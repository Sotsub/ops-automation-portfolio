## Problems found and fixed on the way

| Problem | Cause | Fix |
| --- | --- | --- |
| Open orders showed the status "Draft" although they were submitted | Creating a document with `docstatus: 1` in one request skips the step where ERPNext sets the status | The seeder saves a draft, then submits it (`PUT docstatus=1`), as the ERPNext screens do |
| ERPNext queued 30 stock revaluation jobs during the trial | ERPNext treats an existing stock entry with the same timestamp as "in the future". Several invoices on one day all had the time 15:00:00 | Each stock document gets its own minute on its day. Receipts start at 08:00 and shipments at 12:00 |
| `Failed to decrypt key ... api_secret` on a newly built site | A new site has no encryption key until one is needed. The web workers each cache the site config, so several generated their own key | `make erp-up` now creates the key once with `bench`, then restarts the backend (and the frontend proxy) |
| `PermissionError` creating territories | Territories and supplier groups need the Sales and Purchase Master Manager roles | Added to the integration user. `make erp-api-keys` adds missing roles on every run |
| A run crashed after 100 documents (a logging bug) | `created` is a reserved name for log record fields | Renamed. The next run resumed and duplicated nothing, which tested the resume behaviour for real |
